# Орбитальный рейс

3D-игра-симулятор запуска ракеты-носителя на **Next.js 16 + React 19 + TypeScript + three.js**.
Игрок собирает ракету из деталей разной формы, смотрит предстартовый расчёт и запускает её:
неудачная компоновка разваливается в атмосфере, удачная выводит полезную нагрузку на орбиту.

## Что можно выбрать

| Узел | Варианты | На что влияет |
|---|---|---|
| Головной обтекатель | оживальный, конический, затупленный, плоский | сопротивление, волновой пик на трансзвуке, нагрев, положение центра давления |
| Стабилизаторы | нет, малые, большие трапеции, решётчатые | запас устойчивости, демпфирование, сопротивление, масса |
| Двигатель 1-й ступени | 4 модели × 1–4 штуки | тяга, удельный импульс, угол качания сопла |
| Баки обеих ступеней | S / M / L | запас топлива, сухая масса, длина, центровка |
| Двигатель 2-й ступени | вакуумные «Нова-В» и «Эон» | тяга и экономичность на разгоне до орбитальной скорости |
| Полезная нагрузка | 1.5 / 4 / 9 т | масса, которую нужно вывести |

## Модель полёта

Симуляция считается собственным интегратором (полушаговый метод Эйлера, шаг 20 мс) —
физического движка твёрдых тел здесь недостаточно, нужна аэрокосмическая модель:

- **Тяга и расход** — интерполяция между земными и вакуумными характеристиками по давлению.
- **Атмосфера** — экспоненциальная модель плотности и давления, шкала высот 5.6 км, граница 70 км.
- **Аэродинамика** — лобовое сопротивление с трансзвуковым пиком (зависит от формы обтекателя),
  нормальная сила в центре давления, рост сопротивления по углу атаки.
- **Устойчивость** — центр давления по упрощённой методике Барроумена, центр масс пересчитывается
  по мере выгорания топлива; разность даёт запас устойчивости в калибрах.
- **Вращение** — момент от нормальной силы на плече «ЦД–ЦМ», аэродинамическое демпфирование,
  управляющий момент от качания сопла с ограничением скорости перекладки привода.
- **Ветер** — струйное течение с максимумом на 10–11 км и порывы: именно оно проверяет запас устойчивости.
- **Орбитальная механика** — оскулирующие элементы из вектора состояния, апоцентр, перицентр,
  эксцентриситет, время до апоцентра.
- **Наведение** — вертикальный участок, манёвр тангажа, гравитационный разворот с ограничением
  угла атаки, дросселирование на макс. скоростном напоре, баллистическая пауза и довыведение
  в апоцентре с обнулением вертикальной скорости.

## Планета

`src/lib/planet.ts` генерирует планету процедурно, трёхмерным градиентным шумом,
который сэмплируется **прямо на сфере**: направление берётся из широты и долготы
пикселя. Поэтому карта сходится по шву долготы и не размазывается у полюсов —
чего не даёт шум, посчитанный в плоскости UV.

За один проход строятся пять карт:

- **цвет** — биомы по высоте и влажности: глубина океана, шельф, пляжная полоса,
  лес или саванна, скалы, снег на вершинах (снеговая линия опускается к полюсам),
  плюс полярные шапки;
- **высоты** — рельеф в bump-карту, с хребтами по гребням шума на суше;
- **шероховатость** — океан гладкий и бликует на солнце, суша матовая;
- **облака** — широтные пояса поверх объёмного шума;
- **огни городов** — светятся только на ночной стороне, через шейдер по
  направлению на солнце.

Свечение атмосферы — френелевский ободок на отдельной сфере чуть выше границы
атмосферы. Оболочка должна оставаться **ниже** камеры, иначе ободок
разворачивается в купол на весь экран; поэтому она включается только выше 85 км,
а у поверхности небо красит другая, внутренняя оболочка.

Полюса сферы по умолчанию смотрят вдоль ±Y — то есть точно в стартовую площадку
и в плоскость орбиты. Глобус развёрнут на 90°, чтобы трасса шла по экватору,
а не через ледяные шапки.

Карты отдаются буферами и грузятся как `DataTexture` (быстрее, чем через canvas).
Размер: 896 пикселей по долготе на десктопе, 512 на телефоне — режим
определяется медиа-запросом синхронно, до первого рендера React.

## 3D-модели

Ракета собирается не из примитивов, а из кита деталей, сделанного в Blender.
Скрипт `tools/blender/build_kit.py` строит детали процедурно и экспортирует их
в `public/models/rocket-kit.glb`:

```bash
blender --background --python tools/blender/build_kit.py
```

Соглашения кита (иначе сборка в three.js развалится):

- начало координат каждой детали — её **верхняя** точка, деталь уходит вниз по −Z;
  экспортёр переводит Z-up в Y-up, и в three.js деталь уходит по −Y — ровно так,
  как её ставит `layout()` из `src/lib/design.ts`;
- радиусы в метрах, калибр 3 м, как в `DIAMETER`;
- детали переменной длины (обечайки баков, кабель-канал, сопло) сделаны
  **единичными** — игра растягивает их масштабом, а накладные элементы
  (шпангоуты, полосы) ставит отдельными копиями, чтобы растяжение их не искажало.

`src/lib/kit.ts` грузит glb один раз за страницу, `buildRocket()` клонирует детали,
разделяя геометрию и материалы. Пока кит едет по сети, ракета собрана на
примитивах — та же сборка работает и при отказе загрузки.

Кит весит 168 КБ (3900 полигонов, 16 деталей), по сети — 66 КБ gzip и меньше
под brotli, которым Vercel отдаёт статику. Draco к нему не подключён намеренно:
декодер весит больше, чем экономия на такой геометрии. Запекать AO в текстуру
тоже нет смысла — обечайки растягиваются под длину бака, вместе с ними
растянулась бы и запечённая карта.

## Стартовый комплекс

`src/lib/pad.ts` строит площадку вокруг ракеты: бетонное поле, стартовый стол
с газоотражателем и газоходом, кабель-заправочную башню с лифтом и краном, три
фермы обслуживания, молниеотводы с тросами, прожекторные мачты, кабельные
каналы, хранилище компонентов топлива с эстакадой трубопровода, водонапорную
башню, командный бункер под обваловкой и монтажно-испытательный корпус с путём
транспортёра.

Компоновку задают два ограничения:

- **Ничего ниже нуля не видно.** Поверхность планеты проходит ровно через `y = 0`
  и на масштабе площадки плоская, поэтому приямок, вырытый вниз, просто
  просвечивал бы травой. Стартовый стол вместо этого поднят над бетоном,
  газоотражатель стоит внутри него, а газоход уходит от стола по поверхности.
- **Башня не должна закрывать ракету.** Вся крупная застройка вынесена в
  западный сектор, за ракету, а облёт в конструкторе не крутится по кругу, а
  качается в свободном от неё восточном секторе (`LaunchPad.viewAzimuth`).
  Решётки ферм оставлены открытыми по той же причине — сквозь них видно корпус.

Фермы обслуживания встают по высоте именно той ракеты, которая собрана
(`setVehicleLength`), и отводятся к башне по зажиганию (`setRetract`).

Всё неподвижное сливается в несколько мешей по материалам через
`mergeGeometries`: одни только решётчатые фермы — это больше семисот балок, и
отдельными объектами они дали бы столько же вызовов отрисовки. После слияния
на весь комплекс уходит около десяти вызовов, а на всю сцену целиком — меньше
пятидесяти.

## Производительность

`step()` — самое горячее место игры: при ускорении времени ×50 цикл рендера просит
у него до 2500 шагов на кадр, то есть около 150 000 шагов в секунду. Поэтому шаг
интегрирования не выделяет память: вся векторная математика идёт по заранее
заведённому пулу `Vector3`/`Quaternion`, массовая сводка суммируется без
промежуточного массива, а элементы орбиты пишутся в существующий объект.
Замерить запас можно прогоном `npm run bench`.

Если WebGL не запускается (выключено аппаратное ускорение) или браузер теряет
контекст, игра показывает объяснение вместо пустого чёрного холста.

Сцена, наоборот, пересобирается редко — при каждой правке конструкции. Детали
кита клонируются через `Object3D.clone()`, а он **делит** геометрию и материалы
с оригиналом, поэтому `RocketMeshes.dispose()` освобождает только то, что создала
сама сборка: факелы и примитивы резервного варианта. Общий кит и материалы-константы
остаются жить для следующих ракет.

## Что переживает перезагрузку

- **последняя компоновка** — в `localStorage`, читается уже после монтирования
  (страница отдаётся статикой, и чтение при рендере разошлось бы с серверной разметкой);
- **рекорды** — лучший результат по каждой полезной нагрузке, он же виден в конструкторе;
- **ссылка на компоновку** — кнопка «Поделиться» кладёт конструкцию в адрес вида
  `#d=ogive.large.sat.kestrel.s1-m.1.nova.s2-m`. Присланная ссылка задаёт стартовую
  компоновку **один раз**: адрес сразу чистится, чтобы дальнейшие правки игрока
  не откатывались при перезагрузке. Каждое поле проверяется по каталогу деталей —
  устаревшая ссылка даёт значение по умолчанию, а не сломанную ракету.

Всё обращение к хранилищу обёрнуто в `try/catch`: в приватном режиме и при
запрещённых сайтовых данных оно бросает исключение, а игра должна просто работать
без сохранений.

## Как проиграть

- запас устойчивости отрицательный — кувырок и разрушение в потоке;
- слишком большая тяга — разгон в плотных слоях и разрушение корпуса скоростным напором;
- плоский или затупленный обтекатель — потери на сопротивление и прогар/выгорание обтекателя;
- ТВР меньше единицы — ракета не отрывается от стартового стола;
- мало Δv — перицентр остаётся ниже атмосферы, аппарат падает.

Орбита засчитывается при перицентре выше 72 км.

Итог показывается один раз: можно повторить запуск той же ракетой, не возвращаясь
в конструктор, или уйти править компоновку.

## Управление

### Клавиатура

| Клавиша | Действие |
|---|---|
| `C` | смена камеры: сопровождение / сбоку / обзор |
| `A` | автопилот ↔ ручное управление |
| `пробел` или `P` | пауза |
| `←` / `→` | тяга |
| `↑` / `↓` | тангаж в ручном режиме |
| `,` / `.` | ускорение времени (×1 … ×50) |

### Телефон и планшет

Раскладка переключается по медиа-запросу (`useMobile`), а не по ширине окна вслепую:

- **конструктор** — сцена сверху, под ней лист с вкладками «Корпус / 1 ступень / 2 ступень /
  Расчёт»; закреплённая внизу строка показывает ТВР, Δv, запас устойчивости и кнопку запуска;
- **альбомная ориентация** — сцена уезжает влево, конструктор занимает правую половину;
- **полёт** — компактная телеметрия сверху, топливо и кнопки снизу: камера, автопилот,
  пауза, ускорение времени, а в ручном режиме — тангаж и тяга;
- камера считает дистанцию из поля зрения и высоты кадра, свободной от панелей, поэтому
  ракета одинаково хорошо помещается и на телефоне, и на широком мониторе;
- на мобильных устройствах сцена рендерится в облегчённом варианте (меньше звёзд,
  грубее сфера планеты, ограниченный `devicePixelRatio`).

## Разработка

```bash
npm install
npm run dev        # http://localhost:3000
npm run build
npm test           # регрессия баланса без браузера
npm run typecheck  # tsc --noEmit
npm run lint       # eslint (flat config, eslint-config-next)
npm run bench      # скорость интегратора
```

`npm test` прогоняет 19 компоновок без браузера и **сверяет** исход каждой с
ожидаемым — орбита, авария, недолёт. Скрипт завершается с кодом 1 при первом
расхождении, поэтому правка характеристик деталей или физики, ломающая баланс,
видна сразу. Кейсы лежат в `scripts/sim-test.ts` вместе с пояснением, чем каждый
интересен; `npm test -- -v` печатает подробности по каждому прогону.
